Lab 05 — Terraform on FLOCI

Infrastructure as a gated pipeline
05
TERRAFORM ON FLOCI

Infrastructure is not a ticket — it is a pipeline. Webhook triggers it, Terraform plans it, a human approves it, FLOCI receives it. No real AWS, no surprise bill, full audit trail.

01 / What This Lab Proves

PROOF — The same CI/CD loop that builds apps can provision infrastructure: terraform init / workspace select / plan -var-file / apply tfplan behind a Jenkins input gate, with Provider.tf pointing at FLOCI instead of real AWS. Workspace + tfvars isolates dev / stg / prod state.

02 / Steps 1–2 — Prepare Repo + Jenkinsfile

STEP 01 — GitHub repository

Ensure at repo root: VPC.tf (VPC resource definitions), Variables.tf (input variables), Provider.tf (FLOCI endpoint — per 0.4 answer), env var files dev / stg.tfvars / Prod (one per workspace), and Jenkinsfile. Commit & push any missing pieces.
DEVdev.tfvarsworkspace: dev
STGstg.tfvarsworkspace: stg
PRODProd.tfvarsworkspace: prod

ISOLATION RULE

Keep state per-env isolated via workspaces or separate state files so a dev apply cannot affect stg / prod state.

STEP 02 — Jenkinsfile (declarative) — seven stages

pipeline { agent any stages { stage('Checkout') { steps { checkout scm } } stage('Terraform Init') { steps { sh 'terraform init' } } stage('Workspace Select') { steps { sh 'terraform workspace select ${ENV_NAME} || terraform workspace new ${ENV_NAME}' } } stage('Plan') { steps { sh 'terraform plan -var-file=${TFVARS_FILE} -out=tfplan' } } stage('Approve') { steps { input message: 'Apply this Terraform plan?', ok: 'Approve' } } stage('Apply') { steps { sh 'terraform apply -auto-approve tfplan' } } } post { success { echo 'Pipeline succeeded.' } failure { mail to: '<recipient-from-0.4>', subject: "Pipeline Failed: ${env.JOB_NAME} #${env.BUILD_NUMBER}", body: "Check console output at ${env.BUILD_URL}" } } }

Replace ${ENV_NAME} / ${TFVARS_FILE} via build parameters (choice: dev / stg / prod). input implements the Approve / Abort branch — declining aborts before apply.

03 / Steps 3–4 — Configure Job & Provider

STEP 03 — Pipeline job in Jenkins

Create (or reuse) a Pipeline job pointing at the GitHub repo → Pipeline script from SCM so it reads the Jenkinsfile from the repo. Set up the GitHub webhook trigger (companion webhook task) so pushes trigger this pipeline automatically.

STEP 04 — Provider.tf → FLOCI

Set the provider block to point at FLOCI's simulated AWS API per 0.4 details — not a real account/region/credentials. Confirm terraform init succeeds. ● FLOCI IS THE UNKNOWN — NEVER GUESS AWS CREDS
# Provider.tf — shape depends on FLOCI docs (get from user in Step 0.4) # example pattern — replace with real FLOCI endpoint/auth terraform { required_providers { aws = { source = "hashicorp/aws" } } } provider "aws" { region = "us-east-1" endpoints { ec2 = "https://floci.example.internal" } # ← FLOCI simulated API # credentials = FLOCI token / API key — not real IAM } # then $ terraform init Initializing provider plugins... success

HUMAN — AT GATE

Approve → pipeline continues to apply tfplan
Abort → pipeline stops, apply never runs
No auto-approve — gate exists to prevent unreviewed infra changes.

WHY THE GATE EXISTS

Automation stops where human risk judgment is required. input message: 'Apply this Terraform plan?' is the amber checkpoint between knowing and doing. Do not auto-approve unless explicitly instructed.

06 / Verify Checklist

  • Each stage completes: CHECKOUT → INIT → WORKSPACE → PLAN then pipeline PAUSES at Approve.
  • Select stg workspace → plan diff matches stg.tfvars (wrong diff = wrong workspace/tfvars or Provider still points to real AWS).
  • Approve → Apply runs and FLOCI reflects simulated VPC + Subnets + EC2 + S3.
  • Abort → Apply does not run, pipeline stops cleanly, plan discarded.
  • Introduce invalid HCL → failure mail arrives at <recipient-from-0.4> (requires SMTP configured).
  • Push a new commit → webhook re-triggers the same pipeline (Lab 01 trigger reused).

GOTCHA — FLOCI IS NOT AWS

Do not paste real IAM roles, ~/.aws/credentials, or account IDs into Provider.tf and expect FLOCI to work. FLOCI is a simulation — its provider block, endpoint, and auth are bespoke. Ask for them in Step 0.4 or the pipeline will target the wrong control plane.

08 / Proof — What This Lab Proved

PROOF — Infrastructure under the same lifecycle as application code: versioned in Git, planned as an artifact (tfplan), approved by a human gate, applied to an environment, observable via FLOCI state, and notified on failure — without touching real AWS.
