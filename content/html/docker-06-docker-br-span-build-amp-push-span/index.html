01 / Two Views of the Same Pipeline

The core flow is four operations (Build → Login & Tag → Push) fed by a Git source and the Jenkins credentials store. The extended flow is the seven numbered stages that Jenkins actually executes, ending with an optional deployment into FLOCI's simulated AWS — not real cloud.

04 / Steps 1–2 — Repository & Credentials

01 — Prepare the Repository

Ensure the repo contains hello.py · requirements.txt · Dockerfile · Jenkinsfile (built in Step 3). Commit missing pieces and push. Skip/reuse anything already present.

02 — Add Docker Hub Credentials to Jenkins

Manage Jenkins → Credentials → Add
Kind: Username with password
Username = Docker Hub user
Password = access token (not account password)
ID = dockerhub-creds

NEVER — Hardcoded in Jenkinsfile

sh 'docker login -u myuser -p s3cret123' ← in Git history forever

Secret visible in SCM, logs, and diffs. Revoking means rewriting history.

ALWAYS — withCredentials Binding

withCredentials([usernamePassword(credentialsId: 'dockerhub-creds',
usernameVariable: 'DOCKER_USER', passwordVariable: 'DOCKER_PASS')]) {
sh 'echo $DOCKER_PASS | docker login -u $DOCKER_USER --password-stdin'
}

Injected at runtime, masked in logs, never stored in Git. Token scoped & revocable.

Pipeline as Code

Step 3 — Jenkinsfile · seven stages

05 / Full Jenkinsfile — Seven Stages

Structure matches Image 3's numbered flow. IMAGE_TAG = build-${env.BUILD_NUMBER} makes every build immutable. The last stage is conditional — only runs when DEPLOY_TO_FLOCI == true.

pipeline { agent any environment { IMAGE_NAME = "myusername/app" IMAGE_TAG = "build-${env.BUILD_NUMBER}" } stages { stage('Environment Setup') { steps { echo 'Loading environment/config...' } } stage('Code Checkout') { steps { checkout scm } } stage('Docker Build') { steps { sh "docker build -t ${IMAGE_NAME}:local ." } } stage('Authentication') { steps { withCredentials([usernamePassword(credentialsId: 'dockerhub-creds', usernameVariable: 'DOCKER_USER', passwordVariable: 'DOCKER_PASS')]) { sh 'echo $DOCKER_PASS | docker login -u $DOCKER_USER --password-stdin' } } } stage('Image Tagging') { steps { sh "docker tag ${IMAGE_NAME}:local ${IMAGE_NAME}:${IMAGE_TAG}" } } stage('Image Push') { steps { sh "docker push ${IMAGE_NAME}:${IMAGE_TAG}" } } stage('Application Deployment') { when { expression { return params.DEPLOY_TO_FLOCI == true } } steps { // FLOCI interface depends on Step 0.4 — fill per user-supplied details echo "Deploying ${IMAGE_NAME}:${IMAGE_TAG} into FLOCI simulation..." } } } }

Gotchas & Failure Modes

What breaks and how to recover

10 / Gotchas

GOTCHA — NEVER HARDCODE THE SECRET

Putting the Docker Hub password/token directly in the Jenkinsfile commits it to Git history forever. Always use withCredentials([usernamePassword(credentialsId: 'dockerhub-creds', ...)]) with --password-stdin. The token is masked as **** in logs.

GOTCHA — ACCESS TOKEN, NOT ACCOUNT PASSWORD

Docker Hub access tokens are scoped and revokable per purpose. Generate under Account Settings → Security → New Access Token. If the token leaks you revoke one token, not the whole account. The stored Jenkins credential's password field holds the token.

GOTCHA — DOCKER-IN-DOCKER vs SOCKET MOUNT

Don't assume the execution model. Run docker info on the actual Jenkins agent to confirm whether it uses a mounted /var/run/docker.sock or Docker-in-Docker. Wrong assumption → Cannot connect to the Docker daemon at build time. Decide in Step 0.

GOTCHA — FLOCI IS NOT REAL AWS

The Application Deployment stage is FLOCI-specific. Real AWS CLI/ECR docs do not apply. Get the actual FLOCI interface and deploy command from the user in Step 0.4 — don't guess at syntax. Stage 07 stays when { DEPLOY_TO_FLOCI == true } so the pipeline passes without it when out of scope.

GOTCHA — REPO VISIBILITY & FIRST PUSH

Docker Hub auto-creates the repository on first push if the account allows. Confirm expected visibility (public vs private) before pushing. A private repo with a public assumption breaks downstream pulls.

13 / Interview Checks

WHY withCredentials + --password-stdin?

Injects the secret as env vars at runtime, masks it in logs (****), avoids it appearing in process args or Git history. --password-stdin keeps it out of ps.

WHY build-${BUILD_NUMBER} NOT latest?

latest is mutable and unrepeatable. build-N is immutable — you can roll back to any N, and every deploy is traceable to one Jenkins build.

WHY IS STAGE 07 CONDITIONAL?

FLOCI is a simulation, not always in scope. when { DEPLOY_TO_FLOCI == true } lets the same Jenkinsfile cover both flows — pipeline passes with 6 stages when deployment is out of scope, 7 when in.

WHAT DOES A GREEN BUILD NOT PROVE?

It proves the checks in that pipeline passed — build, login, push. It doesn't prove the app works in production. Registry presence ≠ runtime correctness.
