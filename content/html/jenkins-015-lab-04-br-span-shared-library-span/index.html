Reuse as a Dependency

Why a library exists
04
SHARED LIBRARY

Copy-paste is not reuse. A pipeline library is a versioned dependency: reviewed, pinned, rolled back — one class serving every pipeline. This lab proves a single UatInput class can gate two pipeline styles by checking one workspace file.

01 / What This Lab Proves

PROOF — A Global Pipeline Library hosted on GitHub (src/com/<you>/UatInput.groovy) exposes buildIsUatApproved() → checks tools/approved.txt → returns true / false. Both a scripted pipeline and a declarative when gate consume the same class via @Library('shared-library'). Break the library → all consumers break; revert → all fix. ● REUSE PROVED

The library repo is the source of truth. Jenkins resolves it at build start (not at job save) — every build fetches the pinned version. fileExists('tools/approved.txt') is evaluated inside the consumer's workspace, not inside the library repo.

WHY THIS EXISTS

Without a shared library, every pipeline re-implements the same Groovy logic — drifts, diverges, and cannot be audited. A library moves that logic to one reviewed file with a version, so a fix or a regression propagates consistently.

05 / Step 1 — Create the Shared Library Repository on GitHub

01 — Create or reuse · jenkins-shared-library

If the repo does not exist → create on GitHub (public preferred for this lab). If it exists, confirm src/com/<yourname>/UatInput.groovy is present; if not, add it. Commit to master or main — note which, because Default version must match exactly. Copy the HTTPS clone URL for Step 2.

# UatInput.groovy — approval check (package must match path) package com.nabawy class UatInput implements Serializable { boolean buildIsUatApproved() { return fileExists('tools/approved.txt') } } # → stored at: src/com/nabawy/UatInput.groovy → import com.nabawy.UatInput

The method is intentionally trivial: file existence in the consumer's workspace is the approval signal. No hard-coded paths in the library beyond the relative check — the workspace decides.

Consume — Scripted Pipeline

Steps 3 to 4 · Sandbox off · First proof

07 / Step 3 — Create the Test Pipeline Job

03 — New Item → Pipeline · shared-library-test-pipeline

Check Jenkins for an existing pipeline job for this test — reuse if configured similarly. Otherwise create shared-library-test-pipeline. In Pipeline section → uncheck Use Groovy Sandbox.

SANDBOX OFF — WHY

With sandbox on, fileExists and library class construction trigger script approvals. Disabling it avoids approval noise for this minimal class. Production alternative: keep sandbox on and approve signatures via Manage Jenkins → In-process Script Approval.

VERSION PIN —
@Library('shared-library') _ tracks Default version (live).
@Library('shared-library@main') _ pins to main branch.
@Library('shared-library@v1.2') _ pins to a tag — reproducible builds.
Pin when you want stability; track when you want shared standards.

08 / Step 4 — Scripted Pipeline That Uses the Library

Exact name + exact import path — both are load-bearing. The package must mirror the folder: src/com/nabawy/UatInput.groovy → com.nabawy.UatInput.

# Pipeline script — scripted style (Pipeline → Definition: Pipeline script) @Library('shared-library') _ import com.nabawy.UatInput def uatInput = new UatInput() println "Build is UAT approved: ${uatInput.buildIsUatApproved()}"

VERIFY — Run the build · inspect Console Output

With tools/approved.txt present in the workspace → console prints Build is UAT approved: true true
Without the file (or renamed) → Build is UAT approved: false false
The build itself does not fail in either case — the method only reports state.

# expected console — both outcomes # with file: Build is UAT approved: true # without: Build is UAT approved: false — pipeline still green, value drives the gate in Step 5
WITH FILE tools/approved.txt exists ● TRUE
WITHOUT tools/approved.txt missing ○ FALSE

DECISION CHECK

The scripted pipeline reports approval. The declarative pipeline in Step 5 acts on it — skipping a stage without failing the build. Same class, two consumption modes.

Gate & Validate

Step 5 declarative when · Step 6 end-to-end

09 / Step 5 — Declarative Pipeline with when Gate

Replace the scripted script with a declarative pipeline that uses the same class inside a when { expression { … } } condition. The library instance must be created outside the pipeline { } block.

@Library('shared-library') _ import com.nabawy.UatInput def uatInput = new UatInput() pipeline { agent any stages { stage('Run only if approval exists') { when { expression { return uatInput.buildIsUatApproved() } } steps { echo 'The build has been approved.' // real build steps here — mvn / docker / ant / deploy } } } }

EXPECT — Stage runs only when approved.txt exists

With file → stage executes and echoes The build has been approved. PASSED
Without file → stage is skipped — no output from inside when, and crucially no build failure. The gate is a state transition, not an error. SKIPPED

# stage view # with tools/approved.txt: [Run only if approval exists] ● PASSED — echo printed # without file: [Run only if approval exists] ○ SKIPPED — when returned false, build green

VERSION PIN — REPRODUCIBILITY NOTE

Unpinned @Library('shared-library') follows Default version — convenient for rolling out shared standards, risky for release reproducibility. Pin consumers with @Library('shared-library@main') or a tag (@v1.4) when a build must be replayable byte-for-byte.

GOTCHA — NAME & BRANCH ARE LOAD-BEARING

shared-library vs shared_library vs Shared-Library are three different libraries to Jenkins. master vs main silently breaks resolution if mismatched. Validate catches the second; only the console catches the first — at build time.

INTERVIEW CHECK — WHY MODERN SCM?

Modern SCM uses the Jenkins SCM API (GitHub Branch Source) so the library is resolved via the native GitHub integration — credentials, webhooks, and branch discovery are consistent with the rest of Jenkins. Legacy SCM is a raw Git clone with fewer guarantees.

INTERVIEW CHECK — WHY fileExists, NOT A PARAMETER?

A file in the workspace is auditable — it appears in the commit history, the checkout, and the artifact. A boolean parameter lives only in Jenkins. For UAT, the approval file is the evidence, not just the signal.
