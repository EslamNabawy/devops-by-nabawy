EXECUTIVE SUMMARY

The Task — In One Paragraph

📖 5 MIN

Provision a public Application Load Balancer in front of two frontend EC2 instances (public subnets) and an internal Application Load Balancer in front of two backend EC2 instances (private subnets). Four custom security groups, two target groups with HTTP health checks, two listeners, four target-group attachments, plus the surrounding VPC plumbing. Use Terraform 1.x with the hashicorp/aws ~> 5.0 provider — exactly the modern arguments from the official docs — and drive dev/staging/prod with workspaces so one codebase ships three environments.

🔑 TIER 1 — PUBLICinternet → public ALB → frontend EC2 ×2. SG allows 80/443 from the world. The front door.
🔑 TIER 2 — INTERNALfrontend + VPC CIDR → internal ALB → backend EC2 ×2. SG chains by reference. Defense-in-depth.

SECTION 03 · THE PIN & THE SWITCH

🏛️ versions.tf + providers.tf

⏱ 7 MIN
§3versions.tf — the pin that makes it portable
terraform { required_version = ">= 1.6.0, < 2.0.0" required_providers { aws = { source = "hashicorp/aws" version = "~> 5.0" } } }
  • ~> 5.0 means 5.x but not 6.0 — roll forward to bug-fixes without re-approval.
  • Commit the auto-generated .terraform.lock.hcl so a teammate's init downloads the same provider bytes.
§4providers.tf — Floci or real AWS with one variable
provider "aws" { region = var.region access_key = "test" secret_key = "test" skip_credentials_validation = true skip_metadata_api_check = true skip_requesting_account_id = true s3_use_path_style = true insecure = true dynamic "endpoints" { for_each = var.floci_endpoint != null ? [1] : [] content { ec2 = var.floci_endpoint elb = var.floci_endpoint elbv2 = var.floci_endpoint iam = var.floci_endpoint sts = var.floci_endpoint s3 = var.floci_endpoint } } }
🔑 THE TRICKThe dynamic "endpoints" block: when var.floci_endpoint is null the block is empty → real AWS. When it points at Floci → every API the provider might call (ec2, elb, elbv2, iam, sts, s3) is redirected. One variable, two worlds.
⚠ THE BUG I HIT AND FIXEDThe elbv2 line is mandatory for ALBs — the classic elb endpoint only serves CLBs. A missing elbv2 line makes aws_lb silently call real AWS even with TF_VAR_floci_endpoint set.
💡 WHY THE FLAGSinsecure = true plus the four skip_* flags are LocalStack/Floci-friendly defaults — they strip TLS, IMDS, account-ID and STS validation that's pointless when the API is a stub.

SECTION 07 · MAIN.TF I

🌐 Networking + the 4 Security Groups

⏱ 7 MIN
§7.1Networking foundation — always first
  • data "aws_availability_zones" "available" gives real AZ names — never hard-code them.
  • Then: aws_vpc · aws_internet_gateway · aws_subnet.public · aws_subnet.private · aws_route_table.public (IGW default route) · aws_route_table.private.
  • Two aws_route_table_association blocks use count = length(aws_subnet.public) / length(aws_subnet.private) — the count-over-a-list lesson: going from 2 AZs to 1 shrinks the code without touching the associations.
§7.2Security groups — each its own resource so changes review cleanly
SGIngressWhy
public_albTCP 80/443 from 0.0.0.0/0Internet-facing load balancer.
internal_albTCP 80 from frontend_ec2 SG and VPC CIDRDefense-in-depth.
frontend_ec2TCP 80 from public_alb SG onlyALB → EC2 path.
backend_ec2TCP 80 from internal_alb SG onlyInternal traffic only.
🔑 THE DEPENDENCY CHAINThe two SG pairs that reference each other (frontend_ec2 ↔ public_alb, backend_ec2 ↔ internal_alb) form a dependency chain Terraform resolves automatically — the SGs are created in topological order, no depends_on needed.
⚠ READ THE CHAIN ALOUDworld → public ALB → frontend EC2 → internal ALB → backend EC2. Traffic can only flow down the chain, and every hop narrows the source. There is no path from the internet to the backends — that's the design.
🎓 EXAMMemorize the 4 SGs and their ingress: public_alb (80/443 from world) · internal_alb (80 from frontend SG + VPC CIDR) · frontend_ec2 (80 from public_alb SG only) · backend_ec2 (80 from internal_alb SG only).

SECTION 07 · MAIN.TF II

🖥️→⚖️ EC2 Fleet + the Public ALB Quartet

⏱ 8 MIN
§7.3EC2 fleet (2 + 2)

data "aws_ami" "amazon_linux" looks up the latest amzn2 AMI so the code never pins an outdated AMI id. aws_instance.frontend / .backend use count with a user_data script installing Apache and serving a workspace-aware page — so the health-check / path returns 200 the moment the instance boots. Spread across AZs: subnet_id = aws_subnet.public[count.index % length(...)].id.

⚠ FLOCI NOTEFloci's EC2 returns instances in terminated state, which crashes Terraform's state serializer. The IaC is correct and works on real AWS — run-alb.sh excludes the EC2 + TG-attach targets from the Floci apply so the rest verifies end-to-end.
§7.4Public ALB — the canonical quartet
resource "aws_lb" "public" { name = "${local.name_prefix}-pub-alb" load_balancer_type = "application" internal = false # ← internet-facing security_groups = [aws_security_group.public_alb.id] subnets = aws_subnet.public[*].id tags = merge(local.common_tags, { Name = "${local.name_prefix}-pub-alb" }) } resource "aws_lb_target_group" "public" { name = "${local.name_prefix}-pub-tg" port = 80 protocol = "HTTP" target_type = "instance" vpc_id = aws_vpc.this.id health_check { enabled = true path = var.health_check_path port = "traffic-port" matcher = var.health_check_matcher interval = 30 timeout = 5 healthy_threshold = 2 unhealthy_threshold = 3 } tags = merge(local.common_tags, { Name = "${local.name_prefix}-pub-tg" }) } resource "aws_lb_listener" "public_http" { load_balancer_arn = aws_lb.public.arn port = 80 protocol = "HTTP" default_action { type = "forward" target_group_arn = aws_lb_target_group.public.arn } } resource "aws_lb_target_group_attachment" "public" { count = length(aws_instance.frontend) target_group_arn = aws_lb_target_group.public.arn target_id = aws_instance.frontend[count.index].id port = 80 }
🔑 THE CANONICAL QUARTETLoad balancer + target group + listener + attachment. Every ALB stack in AWS needs at least these four blocks per tier — and these four resources are exactly what the internal tier copies.

SECTION 07 · MAIN.TF III

🔒 Internal ALB + Health-Check Anatomy

⏱ 6 MIN
§7.5Internal ALB — same quartet, internal = true

The internal block is the public block copied with internal = true, swapped security group (internal_alb), swapped subnets (private), swapped target group, swapped instance set (backend). The name changes (int vs pub) keep ALB names unique in AWS.

public: internal = false · pub SG · public subnets · frontend TG ⇄ internal: internal = true · int SG · private subnets · backend TG
§7.6Health-check anatomy — every line, one meaning
health_check { enabled = true path = "/" # GET / on each target port = "traffic-port" # follow the TG port (80) matcher = "200" # expect HTTP 200 interval = 30 # probe every 30 s timeout = 5 # give up after 5 s healthy_threshold = 2 # 2 passes → healthy unhealthy_threshold = 3 # 3 fails → unhealthy }
💡 TUNING RULESThe numbers are tuned for a small backend. Rule of thumb: interval ≥ 2 × timeout (a probe must finish before the next fires) and healthy_threshold + unhealthy_threshold = 5 for fast convergence on small fleets.
⚠ WHY THE HEALTH CHECK IS THE STARThe ALB only routes to healthy targets. If your app serves / with anything but the matcher code, the TG marks everything unhealthy and the ALB returns 503s — while every instance is technically running. The health check is the contract between the LB and the app.
🎓 EXAMInternal-vs-public differences: internal flag · SG · subnets · TG · instance set — five swaps, one copied quartet. Health check contract: GET path, expect matcher, interval/timeout/thresholds as tuned.

📤 outputs.tf — What the Platform Consumes

Outputs are this stack's contract — ten values that DNS, autoscaling, and observability stacks will reference:

OutputPurpose
vpc_idFor peering / TGW / observability stacks.
public_subnet_idsFor ASGs, Lambda ENIs, etc.
private_subnet_idsSame.
public_alb_dns_nameRoute53 alias records, app config.

internal_target_group_arnSame.

🔑 WHY THE ZONE IDA Route53 alias record to an ALB needs both the DNS name and the ALB's hosted zone ID — that's why public_alb_zone_id is exported separately. Forgetting it breaks the alias Terraform-side.
💡 TG ARNS EXIST FOR AUTOSCALINGAn ASG can register itself with a target group directly via target_group_arn — exporting both TG ARNs means a future autoscaling stack attaches to the ALB without editing this code.
🎓 EXAMCount them: 1 VPC + 2 subnet sets + 2 DNS + 1 zone ID + 2 TG ARNs + 2 instance sets = 10 outputs. Every one exists because some other stack will need it — outputs are written for the consumer, not the author.

SECTION 09 · THREE ENVIRONMENTS

🗂️ Workspaces — dev / staging / prod

⏱ 6 MIN
TASK [The command sequence]one codebase, three applies
cd live-verify-floci/alb-cluster export TF_VAR_floci_endpoint=http://localhost:4566 $ terraform init $ terraform workspace new dev # creates + selects $ terraform workspace new staging $ terraform workspace new prod $ ./run-alb.sh dev # apply dev (22 non-EC2 resources) $ ./run-alb.sh staging $ ./run-alb.sh prod $ terraform workspace list default * dev staging prod
🔑 ISOLATION PROOFEach workspace gets its own state file under terraform.tfstate.d/<name>/terraform.tfstate — and its own resources in Floci: 3 separate VPCs, 12 subnets, 12 SGs, 6 ALBs, 6 target groups, 6 listeners, all live. Nothing is shared between environments.
💡 WHERE THE 66 COMES FROMThe cover said "66 resources deployed": ~22 non-EC2 resources × 3 workspaces ≈ 66 live objects in Floci. The EC2 + attachment blocks are coded and state-tracked but excluded from the Floci apply (the terminated-state limitation from page 9).
⚠ THE DEFAULT WORKSPACEFirst init + apply without creating a workspace lands everything in default with an unprefixed state key. Create dev before the first apply — the sequence above is ordered deliberately.
🎓 EXAMThe proof of multi-env: 3 workspaces → 3 state files → 3 complete, separately-named stacks (onext-dev-*, onext-staging-*, onext-prod-*), all from one codebase with zero environment conditionals in the resource blocks — the naming comes from locals.tf.
