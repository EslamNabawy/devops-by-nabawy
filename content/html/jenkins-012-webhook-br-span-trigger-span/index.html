Lab 01

GitHub Webhook Trigger — Concept & Control Loop
01
GITHUB WEBHOOK TRIGGER

One commit should be enough. Push once — Jenkins builds without anyone clicking Build Now. This lab closes the loop commit → webhook → trigger → checkout and proves all three failure points are knowable.

01 / What / Why / When

WHAT

A GitHub webhook POSTs a push event to /github-webhook/. Jenkins matches repo + branch and starts the job that has GitHub hook trigger for GITScm polling enabled.

WHY

Without it, Jenkins only learns about pushes on poll or manual click — minutes late. Webhook moves discovery to seconds and removes the human gate.

WHEN

Every push to the configured branch. The job must already have a valid checkout (PAT + branch match) or the triggered build will fail fast.

WHY THIS EXISTS

Before this lab, delivery depends on a person remembering to click. A broken change can sit unbuilt for hours. The webhook turns intent (push) into execution (build) deterministically — CI starts where the developer already works: Git.

ASK IN ONE BATCH — BEFORE STEP 1

Only ask for what checks proved missing. Typical batch: (1) target repo URL + branch, (2) valid PAT or browser generation, (3) Jenkins public URL / tunnel choice, (4) desired job name. Then run Steps 1–7 uninterrupted.

GOTCHA — WSL / LOCALHOST IS INVISIBLE TO GITHUB

GitHub delivers webhooks over the public internet. A Jenkins on localhost or inside WSL has no public address — GitHub's POST will time out with — or 5xx in Recent Deliveries. Fix: expose Jenkins via ngrok http 8080, localhost.run, or a reverse proxy with a domain — and use that URL as the webhook Payload URL. Decide now in Step 0, or Step 5 will fail silently.

Job · Credentials · Checkout

Steps 1–4 — Make the job green before wiring Git

05 / Step 1 — Create or Reuse a Pipeline Job

OBSERVE — Browse Jenkins dashboard for an existing pipeline job that should own this trigger. Reuse it if it exists.

EXECUTE — Otherwise New Item → Pipeline → name github-webhook-pipeline → Pipeline → Pipeline script → paste a minimal placeholder:

pipeline { agent any stages { stage('Hello') { steps { echo 'hello from webhook lab' } } } }

VERIFY — Save → Build Now → build is PASSED before any Git integration. A red job here means the agent/label is wrong — fix before Step 4.

06 / Step 2 — Repository URL

EXECUTE — In GitHub → repo → Code → HTTPS → copy clone URL:

https://github.com/<username>/<repo>.git

Use HTTPS (PAT-based) — GitHub has deprecated password auth for Git operations.

07 / Steps 3–4 — PAT + Jenkins Credentials + Checkout

WHY CREDENTIALS LIVE IN JENKINS, NOT IN GIT

The pipeline must not contain a raw token. Jenkins stores it as Username with password (username = GitHub user, password = PAT) and injects it at checkout time. The repo history never sees the secret.

OBSERVE — Step 0 already confirmed or collected the PAT. Never attempt to generate one programmatically — it requires the browser.

EXECUTE — Manage Jenkins → Credentials (or inside the job: Pipeline Syntax → checkout: Check out from version control → SCM: Git):

  1. Paste Repository URL.
  2. Add → Jenkins → Username with password — Username = GitHub user, Password = PAT, ID = github-token → Add.
  3. Select github-token from the dropdown.
  4. Branch to build = the exact branch from Step 0 (e.g. */main).
  5. Generate Pipeline Script → copy snippet → paste into job Pipeline → Save.
# generated snippet — use the one Jenkins generates for you checkout([$class: 'GitSCM', branches: [[name: '*/main']], userRemoteConfigs: [[url: 'https://github.com/<user>/<repo>.git', credentialsId: 'github-token']]])

VERIFY — Build Now → Console Output shows Cloning the remote Git repository → Checking out Revision <sha> → PASSED. If checkout fails, check PAT scope (repo), credential ID, and branch spelling first.

Wire Both Sides

Steps 5–6 — GitHub webhook + Jenkins trigger must agree

08 / Step 5 — GitHub Webhook

OBSERVE — Repo → Settings → Webhooks. If a webhook already points at …/github-webhook/ and shows a green checkmark → reuse it, skip to Step 6.

EXECUTE — Add webhook:

FieldValue
Payload URLhttp://<your-jenkins-url>/github-webhook/ — trailing slash required
Content typeapplication/json
EventsJust the push event (default)
Activechecked
Save.

VERIFY — Webhook list shows a green checkmark on the initial ping delivery. Click the webhook → Recent Deliveries → 200 and a JSON payload. A FAILED delivery here is a reachability problem, not a Jenkins config bug — re-check the public URL chosen in Step 0.

# GitHub → webhook → Recent Deliveries (success) Request URL: http://<jenkins-url>/github-webhook/ Status: 200 OK Event: ping # failure looks like: Status: — Could not connect / Timed out → Jenkins not publicly reachable (WSL/tunnel)

09 / Step 6 — Jenkins Trigger

OBSERVE — Open the job → Configure → Build Triggers. Is GitHub hook trigger for GITScm polling already checked? If yes → nothing to do.

EXECUTE — Check GitHub hook trigger for GITScm polling → Save.

VERIFY — Job config now lists the trigger; no other trigger (e.g. Poll SCM) is needed. The webhook and the checkbox are the two halves of one contract — both must be present.

WHY TWO SIDES?

GitHub sends; Jenkins listens. Missing the Payload URL → no event arrives. Missing the trigger checkbox → the event arrives but Jenkins ignores it. Recent Deliveries = 200 proves delivery; a new auto build proves the listener reacted.

Prove It

Step 7 — End-to-end test · Failure map · What green proves

10 / Step 7 — End-to-End Automatic Trigger

EXECUTE — Make a small commit on the configured branch:

$ echo "<!-- webhook trigger $(date -Iseconds) -->" >> index.html $ git commit -am "trigger: verify webhook" && git push # then — do NOT click Build Now

OBSERVE — Watch Jenkins Build History for ~5–15 s. A new build should appear with cause Started by GitHub push by <user>.

VERIFY — Three signals, all must hold:

  • Build History shows an automatic build (not manual) — PASSED.
  • Console Output → checkout SHA equals git log -1 --oneline of the pushed commit.
  • GitHub → Settings → Webhooks → Recent Deliveries for this push → 200.
# Jenkins console — proof the new commit arrived Started by GitHub push by eslamn Checking out Revision a3f9c1e (refs/heads/main) > git rev-parse refs/remotes/origin/main^{commit} # matches pushed SHA Finished: SUCCESS

12 / Proof — What This Lab Proved

PROOF — A file edit + git push started a Jenkins build without Build Now. The loop commit → webhook → trigger → checkout → build is closed. Reachability + credentials + branch match are the only three invariants. ● WEBHOOK PROVED

INTERVIEW CHECK

Why does /github-webhook/ need a trailing slash?
Jenkins registers that exact path. Without the slash GitHub follows a redirect that Jenkins does not treat as a delivery — Recent Deliveries shows a 3xx not a 200.

CONSISTENCY RULE

Every pipeline state uses color + symbol + label — it remains readable when printed in grayscale. Green = passed/deployed, blue = running/info, amber = waiting, red = failed/blocked.
